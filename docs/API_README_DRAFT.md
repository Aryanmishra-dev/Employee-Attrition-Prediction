# API README

Base URL for local development:

```text
http://127.0.0.1:8000
```

Authentication is optional for local demos and can be enabled with `APP_AUTH_TOKEN` or `APP_AUTH_USERNAME` / `APP_AUTH_PASSWORD`. Enable it before exposing this application outside a trusted development environment.

## Health

```http
GET /health
```

Response:

```json
{"status":"ok"}
```

## Predict One Employee

```http
POST /api/predict
Content-Type: application/json
```

Request body must match the `EmployeePredictionInput` schema. Key fields include age, department, job role, tenure, compensation, satisfaction, overtime, and performance inputs.

## Batch Preview

```http
POST /api/batch-preview
Content-Type: multipart/form-data
```

Form field:

```text
file=<csv file>
```

Returns an HTML partial for HTMX. The CSV must contain the required prediction fields, excluding optional `EmployeeNumber`.

## Batch Prediction

```http
POST /api/batch-predict
Content-Type: multipart/form-data
```

Form field:

```text
file=<csv file>
```

Returns either an HTML partial for HTMX or a JSON `BatchPredictionResponse` for non-HTMX clients.

Recommended production controls:

- Maximum upload size.
- Maximum row count.
- CSV dialect validation.
- Background processing for large files.
- Per-user quota and rate limiting.
- Export expiration.

## Download Batch Results

```http
GET /api/batch-results/{batch_id}/download
```

Returns a CSV export generated by the batch prediction route.

Production recommendation: require authorization and verify that the requesting user owns or is allowed to access the batch.

## Employee Profile

```http
GET /api/employee/{employee_id}
```

Returns employee details, latest prediction, contribution drivers, and notes.

## Add Employee Note

```http
POST /api/employee/{employee_id}/notes
Content-Type: application/x-www-form-urlencoded
```

Fields:

```text
note=Follow up with manager this month
author=HR Partner
```

Returns an HTML partial for HTMX.

Production recommendation: validate author from the authenticated user, not from a request field.

## Analytics

```http
GET /api/analytics/summary
GET /api/analytics/department
GET /api/analytics/trends
GET /api/analytics/top-features
GET /api/analytics/age-groups
GET /api/analytics/income-scatter
```

Several endpoints accept `partial=1` or `partial=heatmap` and return HTML partials for HTMX.

## Error Shape

Validation and parsing errors return:

```json
{
  "error": "Validation Error",
  "detail": "field: reason"
}
```

## Security Notes

- Treat prediction inputs and outputs as sensitive HR data.
- Add authentication, authorization, CSRF protection, rate limits, and audit logging.
- Avoid returning employee data to unauthenticated clients.
- Avoid storing full raw employee inputs unless there is a clear retention policy.
