# Employee Attrition Prediction

Production-style employee attrition prediction web application built with FastAPI, HTMX, Jinja2, Tailwind CDN, and a pure NumPy inference engine.

## What is included

- Dashboard with summary cards, risk donut chart, department attrition bar chart, recent predictions, and quick-predict modal
- Single employee prediction flow with HTMX form submission and inline result card
- Batch CSV preview, scoring, sortable/filterable results table, and CSV export
- Employee profile page with radar chart, contribution chart, recommendations, and note storage
- Analytics page with lazy-loaded HTMX chart partials
- Model info page with metrics, confusion matrix, feature importance table, and methodology notes
- Append-only prediction logging for downstream analytics
- ASGI entrypoint for platform deployment

## Local setup

1. Install dependencies:

```bash
python3 -m pip install -r requirements.txt
```

1. Rebuild the model artifact if needed (requires `scikit-learn`):

```bash
python3 -m pip install scikit-learn==1.8.0
python3 scripts/train_model.py
```

1. Run the FastAPI app:

```bash
uvicorn app.main:app --reload
```

1. Run the smoke test:

```bash
python3 scripts/smoke_test.py
```

1. Open:

```text
http://127.0.0.1:8000
```

## Environment variables

Use `.env.example` as the starting point.

- `HIGH_RISK_THRESHOLD=0.65`
- `MEDIUM_RISK_THRESHOLD=0.35`

## Notes

- The packaged artifact is created from the IBM HR dataset and mirrors the notebook-inspired preprocessing flow.
- The notebook `ml-flow-of-ibm.ipynb` was used as the training reference, but the deployable serving artifact is generated by `scripts/train_model.py`.
- The deployment model uses a pure NumPy inference pipeline (without runtime `scikit-learn` or `scipy`) to keep the production image lean.
- Batch uploads and note submission require `python-multipart`.
